## D-001 部署地域：中国大陆

**决策：** 生产、staging、备份均位于中国大陆，具体云厂商和地域在购买服务器时确定（建议主地域华东，备份地域华北或华南）。

**影响：**

- **ICP 备案：** 面向公网的域名在 80/443 提供服务前必须完成 ICP 备案；上线后按要求办理公安联网备案。备案周期计入 Sprint 8 之前的关键路径，建议 Sprint 0 即启动。
- **备案主体：** 个人备案对网站内容和交互功能可能有限制，需在启动备案时向云厂商确认“带用户注册的健康记录类应用”能否以个人主体备案；否则需评估企业主体。
- **个人信息保护法（PIPL）：** 健康信息属于敏感个人信息，需要：
  - 告知处理目的、方式和必要性，并取得**单独同意**；
  - 处理前完成个人信息保护影响评估（PIIA）并留存记录；
  - 提供查阅、复制、更正、删除和撤回同意的途径。
- **生成式 AI 合规：** MVP 只对受邀家庭成员开放。若将来向公众开放，需先评估《生成式人工智能服务管理暂行办法》等规定下的备案和安全评估义务。
- **数据不出境：** 所有组件（含 AI Provider、身份服务、备份、日志、错误追踪）必须处理和存储在境内。
- **网络环境：** Docker Hub、GitHub、npm 和 PyPI 在境内可能不稳定，见 D-013。

## D-002 访问方式：公网 + 邀请制

**决策：** 生产环境通过公网 HTTPS 提供访问，但关闭开放注册，只有持有邀请的用户才能创建账号。

**设计要点：**

- 在 Logto 中关闭自助注册；由应用 `invitations` 表签发一次性邀请（随机 token 只保存哈希、7 天过期、绑定邮箱、只能使用一次）。
- 邀请流程：
  1. admin 在应用中创建邀请，API 通过 Logto Management API 预创建该邮箱的 Logto 用户（不设密码）。
  2. 被邀请人收到邮件链接 `/invite/{token}`，BFF 把 token 哈希暂存到 10 分钟有效的 HttpOnly Cookie 中，然后跳转到登录页。
  3. 被邀请人用邮箱验证码首次登录，之后在 Logto 中设置密码。
  4. 回调时 API 校验：邀请有效、Token 中已验证的邮箱与邀请邮箱一致，然后创建内部用户并把邀请标记为 `accepted`。
- 首次登录时，如果 OIDC subject 没有对应的有效邀请或已有用户，则拒绝创建内部用户并记录审计事件。
- 撤销或过期的邀请如果已经预创建了 Logto 用户，同时删除该 Logto 用户。
- Staging 不对公网开放：通过安全组 IP 白名单或 SSH tunnel 访问。
- 登录、邀请兑换、导出等端点使用更严格的限流（见 API 设计）。

## D-003 身份服务：自托管 Logto

**决策：** 使用开源版 Logto，与业务栈一起部署，并锁定镜像版本。

**设计要点：**

- 部署位置：与应用同一台服务器上的独立容器，独立子域名 `auth.<domain>`（同样需要备案）。
- 数据库：使用同一 PostgreSQL 实例中的独立 database `logto` 和独立角色，与业务库互不授权。
- 管理控制台（Admin Console）不暴露公网，只能通过 SSH tunnel 访问。
- 登录方式：邮箱 + 密码，并用邮箱验证码完成验证；邮件通过境内 SMTP/邮件推送服务发送。管理员必须启用 TOTP MFA，普通用户可选。
- API 资源：在 Logto 中注册 API Resource（如 `https://api.healthos.internal`），Access Token 的 `aud` 必须等于该值。
- 账号删除时，同时删除 Logto 中对应的用户（由删除工作流调用 Logto Management API）。
- 风险：Logto 自身需要备份和升级。其数据库纳入同一备份策略，升级先在 staging 验证。

## D-004 AI Provider：DeepSeek

**决策：** MVP 唯一的 AI Provider 是 DeepSeek 开放平台（境内）。

| 用途 | 模型 | 原因 |
| --- | --- | --- |
| 饮食照片识别 | `deepseek-flash` | 支持视觉输入和 JSON Output |
| 每日建议 / 每周计划 | `deepseek-flash`（默认，非思考模式） | 成本低、延迟低；结构化输出即可 |
| 离线评估候选 | `deepseek-v4-pro` | 仅用于规划质量对比（不支持视觉） |

> 2026-10-30 查阅官方文档时：`deepseek-flash` 支持 Vision 和 Json Output；`deepseek-v4-pro` 不支持 Vision。模型名和能力以官方文档为准，变更前必须重新评估。

**设计要点：**

- 使用 OpenAI 兼容接口，通过 Provider Adapter 封装；业务代码只使用内部别名 `meal_vision` 和 `planner`。
- 每次调用都记录响应中返回的实际模型版本，因为服务端版本可能变化而别名不变。
- 成本控制：DeepSeek 区分高峰和低谷价格（高峰为工作日 UTC 01:00–04:00 和 06:00–10:00，即北京时间 09:00–12:00 和 14:00–18:00）。自动生成的周计划安排在低谷时段；用户主动触发的请求不受限制。
- **待核实（Sprint 4 前完成）：** DeepSeek 开放平台对 API 数据的保留期限、是否用于训练、删除方式。结论写回本文。如果条款不满足要求，Adapter 可以切换到通义千问 Qwen-VL 等境内 Provider。
- **质量门槛：** Sprint 4 用合成中餐图片集评估，食物 top-3 覆盖率未达标时触发 Provider 替换评估。
- MVP 不设第二 Provider 自动故障转移；AI 不可用时降级为手工录入。

## D-005 浏览器会话：BFF

**决策：** 浏览器不持有 Access Token 或 Refresh Token。

```text
Browser --(HttpOnly cookie)--> Next.js BFF --(Bearer access token)--> FastAPI (内部网络)
                                   |
                                   +--(OIDC code + PKCE)--> Logto
```

**设计要点：**

- Next.js 服务端完成 Authorization Code + PKCE，Token 加密后保存在服务端会话存储中。会话存储使用 PostgreSQL 中独立的 `web` schema 和独立角色，不新增 Redis。
- Cookie：`__Host-healthos_session`，属性为 `Secure; HttpOnly; SameSite=Lax; Path=/`，值只包含随机会话 ID（≥ 256 bit）。
- 会话时长：空闲 3 天过期，绝对时长 14 天过期；Refresh Token 每次使用后轮换；用户退出时撤销服务端会话并调用 Logto 的结束会话接口。
- 敏感操作（导出数据、删除账号）要求最近 10 分钟内重新认证（OIDC `max_age=600` / `prompt=login`）。
- CSRF 防护：所有改变状态的请求同时校验 `Origin`/`Referer` 与自定义请求头 `X-HealthOS-CSRF`（双提交 token）；`SameSite=Lax` 只作为额外防线。
- FastAPI 只在内部网络监听，不对公网暴露；仍然完整校验 JWT（签名、`iss`、`aud`、`exp`），不信任 BFF 传来的任何用户标识头。
- Reverse proxy 只把公网流量转发给 Next.js 和 Logto。

## D-006 用户年龄：18 岁及以上

**决策：** 只服务成年人。

- 首次使用时必须填写出生年份（`birth_year`）；按当前年份计算小于 18 岁时，不创建健康档案并提示无法使用。
- 年龄为自我声明；邀请流程同时提示邀请人只邀请成年家庭成员。
- 档案提供“孕期/哺乳期”选项：选中后不给出热量缺口目标，AI 只输出通用安全建议并提示咨询专业人员。

## D-007 对象存储与备份

**决策：** 生产对象存储自托管 S3 兼容服务；站外备份写入另一地域的云对象存储（如阿里云 OSS）。

**设计要点：**

- 应用只依赖 S3 API，具体实现可替换。
- **待核实（Sprint 1）：** MinIO 社区版近年调整了管理控制台和预构建镜像的分发方式。Sprint 1 需要确认可用的固定版本镜像或构建方式；如果维护成本过高，改为评估 Garage/SeaweedFS，或直接使用云 OSS（私有 Bucket + 服务端加密）。
- 备份工具：PostgreSQL 使用 `pg_dump`/物理备份，对象使用增量同步，统一在客户端加密（如 restic 或 age），密钥不保存在备份所在账号中。
- 备份 Bucket：开启版本控制和保留策略（WORM/合规保留），备份写入凭据只有写权限、没有删除权限，以降低勒索软件风险。
- 备份保留：每日备份保留 35 天（账号删除后，备份中的数据最长在 35 天内淘汰）。

## D-008 营养目标：公式参考值 + 用户确认

**决策：** 热量和宏量营养参考值由**确定性代码**计算，不交给 AI；用户确认后才成为目标。

**公式（`nutrition_formula_v1`）：**

- 基础代谢 BMR（Mifflin-St Jeor）：
  - 男：$BMR = 10w + 6.25h - 5a + 5$
  - 女：$BMR = 10w + 6.25h - 5a - 161$
  - $w$ 为体重 kg，$h$ 为身高 cm，$a$ 为年龄（当前年份减出生年份）
- 每日总能量消耗：$TDEE = BMR \times f$，活动系数 $f \in \{1.2, 1.375, 1.55, 1.725\}$，由用户选择活动水平。
- 目标调整：
  - 维持：$TDEE$
  - 减重：$TDEE - \min(0.15 \cdot TDEE,\ 500)$
  - 增重：$TDEE + \min(0.10 \cdot TDEE,\ 300)$
- 宏量参考：蛋白质 1.0 g/kg，脂肪占能量 20–30%，碳水为剩余能量，膳食纤维 25–30 g。

**安全护栏（任何情况都不可被 AI 或用户输入绕过）：**

- 热量参考值下限：$\max(BMR,\ 1200)$ kcal（女）/ $\max(BMR,\ 1500)$ kcal（男）。
- BMI < 18.5，或选中孕期/哺乳期：不提供减重目标。
- 性别未提供：不计算热量参考值，只允许用户手填目标。
- 用户手填的目标低于下限时，显示提示，但不阻止保存（属于用户自己的决定），AI 也不会据此生成更激进的方案。
- 页面显示“参考值基于通用公式，非医疗建议”。
- 体重变化超过 2 kg 或活动水平变化时，提示重新计算。

## D-009 本地化

- MVP 只提供 `zh-CN` 界面；代码中保留 i18n 结构，但不维护第二语言。
- 单位：kg、cm、kcal、g、分钟。
- 默认时区 `Asia/Shanghai`，允许用户修改。
- 周计划 `week_start` 为周一。
- 紧急提示文案使用中国大陆急救号码 120。

## D-010 定时任务

- Worker 进程内置一个调度循环（每分钟一次），按用户本地时间把到期任务写入 `jobs` 表。
- 幂等键示例：`weekly_plan:{user_id}:{week_start}`、`daily_advice:{user_id}:{local_date}`；依靠唯一约束保证不会重复生成。
- MVP 定时任务：
  - 每周计划草稿：用户开启后，在本地周日 20:00 生成（北京时间的低谷时段）。
  - 每日建议：默认由用户手动触发；用户可开启每天 21:30 自动生成。
  - 清理任务：过期上传、导出包、预签名会话、软删除记录的物理清理，以及 AI 原始输出到期删除。
- 只有在 AI 同意有效时才会入队 AI 相关的定时任务；用户撤回同意后，取消待执行的任务。

## D-011 异步结果通知

- 前端轮询任务状态：起始间隔 2 秒，按 1.5 倍递增，最长 10 秒，最多轮询 2 分钟；之后显示“稍后在记录页查看”。
- 用户离开页面后任务继续执行，结果在相应记录页和首页展示。
- 站内通知和 Web Push 属于 P1。

## D-012 营养数据来源

- MVP 的营养数值只来自 AI 估算和用户修正，界面标注“估算值”。
- 不导入第三方食物成分数据库，避免授权和维护问题。
- 未来如需提高准确度，再评估数据源授权（例如《中国食物成分表》）并单独立项。

## D-013 镜像与依赖源

- 应用镜像由 CI 构建，推送到私有容器仓库（如阿里云 ACR），生产按 digest 拉取。
- 第三方基础镜像（PostgreSQL、Logto、对象存储）先同步到私有仓库并锁定 digest，生产服务器不直接从 Docker Hub 拉取。
- 构建时可使用 PyPI/npm 国内镜像，但锁文件中的哈希校验不能关闭。

## D-014 数据保留期限（Proposed）

| 数据 | 保留期限 | 删除方式 |
| --- | --- | --- |
| 预签名上传/下载 URL | 5 分钟 | 自然过期 |
| 未完成或未被引用的上传文件 | 24 小时 | 清理任务删除 |
| 隔离（quarantined）文件 | 7 天 | 清理任务删除 |
| 饮食照片原图 | 记录存续期间；用户可单独删除照片 | 随记录删除 |
| AI 原始输出（加密） | 30 天 | 到期删除，`parsed_output` 保留 |
| 软删除的业务记录 | 30 天后物理删除 | 清理任务 |
| 导出包 | 生成后 24 小时 | 清理任务删除文件 |
| 账号删除 | 线上数据 7 天内完成清除 | 删除工作流 |
| 加密备份 | 35 天轮换 | 备份保留策略 |
| 审计事件 | 1 年（只含元数据） | 定期清理 |
| BFF 会话 | 最长 14 天 | 过期清理 |
| 邀请 | 7 天或使用后失效 | 定期清理 |

上线前需由项目所有者确认，并与隐私说明保持一致。

## D-015 监控与错误追踪（Open）

约束：数据不出境，不在第三方 SaaS 中保存健康内容，内存占用适合单台 8 GB 服务器。Sprint 1 在以下方案中选择：

- 云厂商自带监控（主机、可用性、告警）+ 容器健康检查 + 本地结构化日志轮换；
- 轻量自托管错误追踪（如 GlitchTip）；
- Prometheus + Grafana（仅在确实需要自定义指标时引入）。

## 仍需项目所有者提供

3. 境内邮件发送服务（Logto 验证码和邀请邮件使用）。
4. DeepSeek 数据处理条款核实结果（Sprint 4 前）。
5. D-014 保留期限确认。
