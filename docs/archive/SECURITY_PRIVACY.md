# HealthOS 安全与隐私设计 v0.1

## 1. 安全目标

1. 只有获得授权的主体能读取或修改健康数据。
2. 单个应用缺陷不会轻易造成跨用户数据访问。
3. 文件、备份、日志和 AI 请求遵守相同的隐私边界。
4. 用户能理解、导出、更正和删除自己的数据。
5. 系统能够检测事件、恢复服务并验证恢复结果。

本文件是工程基线，不是特定市场的法律意见。商业发布前需根据目标地区、用户群和实际数据流完成专业审查。

## 2. 数据分类

| 等级 | 例子 | 要求 |
| --- | --- | --- |
| Restricted | 健康档案、记录、照片、报告、AI 输入输出 | 加密、最小权限、审计、严格保留 |
| Confidential | 邮箱映射、同意、导出、内部用户 ID | 加密、受控访问、不得公开 |
| Internal | 脱敏指标、部署元数据 | 员工/运维范围 |
| Public | 公开产品说明 | 可公开 |

密钥和 Token 属于独立 Secret 类，绝不进入业务数据库普通字段、日志或 Git。

## 3. 威胁模型

### 资产

健康记录和照片、身份会话、AI 数据、备份、审计证据、加密密钥、服务可用性。

### 主要威胁

- 用户修改资源 ID 读取家庭成员或其他用户数据（BOLA/IDOR）。
- 被盗会话、弱 Token 验证或 CSRF 导致冒用。
- 恶意/畸形图片攻击解析库，或超大文件耗尽资源。
- 对象存储误设公开、长期签名 URL 泄露。
- 敏感正文进入应用日志、错误追踪、分析工具或 AI Provider 日志。
- 提示注入让模型泄露其他上下文或越权调用工具。
- 管理员、开发者或供应链依赖滥用权限。
- 勒索软件、主机故障或错误迁移破坏生产和备份。
- 删除不完整，数据仍留在派生文件、导出包、缓存或备份中。

## 4. 核心控制

### 身份与会话

- 成熟 OIDC（自托管 Logto），强制 PKCE、精确 redirect URI、state/nonce。
- 严格校验 Token 签名、issuer、audience、expiry；算法不从不可信输入自由选择。
- BFF 模式：Token 只在服务端加密保存，浏览器只有 `__Host-` 会话 Cookie（D-005）。
- 管理/运维账号和 Logto admin 强制 TOTP MFA；导出、账号删除要求 10 分钟内重新认证。
- 安全 Cookie 使用 `Secure`、`HttpOnly`、`SameSite=Lax`；会话轮换与撤销；空闲 3 天、绝对 14 天过期。
- 关闭自助注册，仅邀请制创建账号（D-002）。

### 授权与隔离

- 默认拒绝，所有查询绑定认证用户。
- 应用层策略 + PostgreSQL RLS；迁移与运行角色分离。
- 跨用户负面测试覆盖 CRUD、批量接口、导出、文件 URL 和异步任务。
- 家庭关系不产生隐式权限；管理员普通界面无“查看全部健康数据”。

### 加密与 Secret

- 外部 TLS，内部链路按部署风险配置 TLS；开启 HSTS。
- 数据卷、对象存储和备份静态加密。
- 应用级加密用于必要的高敏字段或原始 AI 内容，密钥与数据分离并可轮换。
- Secret 通过环境 Secret/专用管理服务注入，禁止 `.env` 提交。

### 文件

- 私有 Bucket、阻止公共访问、最短可用预签名期限。
- 限制类型、大小、像素和压缩比；校验 magic bytes 并安全解码重编码。
- 随机对象键，移除 EXIF，隔离待检文件。
- 未来 PDF/复杂文档接入时加入恶意文件扫描和沙箱处理。

### 日志与审计

- 集中脱敏中间件：Authorization、Cookie、请求正文、查询中的敏感字段一律不记录。
- 审计是追加式、受访问控制、可检测篡改；记录谁、何时、为什么、对哪个对象做了什么，不记录健康正文。
- 错误追踪发送前 scrub，生产采样和访问有审批。

### AI 与第三方

- 使用前明确同意，记录政策版本；撤回后不再发起新的处理。
- 发送最少必要数据，不发送直接标识符。
- 评估 Provider 的保留、训练、删除、地域、分包商和事件响应条款。
- 模型输出视为不可信数据，经 Schema、业务和安全校验后才能展示。

## 5. 备份与恢复

- PostgreSQL 每日加密备份；达到稳定运营后增加连续归档以缩小 RPO。
- 对象存储版本/备份策略与数据库引用一致，避免只恢复一侧。
- 备份复制到独立故障域，密钥与备份分开，访问启用 MFA 和审计。
- 每月至少自动验证可读性；MVP 发布前和之后每季度做隔离环境恢复演练。
- 恢复验证包括记录数量、外键、文件哈希、用户隔离和应用烟雾测试。
- 删除请求在生产快速完成；备份中的数据随既定轮换淘汰，期间不得用于正常恢复以外目的，恢复后重放删除清单。

MVP 目标：RPO 24 小时，RTO 4 小时。实际达成情况必须通过演练证明。

## 6. 隐私 UX

- 收集字段旁说明用途，选填项明确标记。
- AI 同意与服务必要条款分开，拒绝 AI 仍能手工记录。
- 生成前显示使用的数据类别，结果显示来源区间和局限。
- 分享（未来）按对象、数据类别、权限和期限授权，可随时撤销。
- 删除界面说明线上删除和备份淘汰的区别与预计日期。
- 不使用暗黑模式诱导同意或阻碍删除。

## 7. 安全验证清单

### 每次合并

- 单元/集成测试、Secret 扫描、依赖锁定和静态分析。
- OpenAPI 兼容性与数据库迁移升级测试。
- 关键授权策略测试。

### 发布前

- OWASP ASVS 风险适配检查。
- 横向/纵向越权、会话、CSRF/CORS、文件上传和限流测试。
- 容器/依赖漏洞扫描，无未接受的高危项。
- AI 提示注入、数据泄露、危险建议和虚构数据红队测试。
- 备份恢复、密钥轮换和删除流程演练。
- 生产端口、Bucket 公共访问和数据库角色自动检查。

## 8. 事件响应

1. **发现与分级：** 记录时间、受影响系统和数据类别，禁止在普通聊天复制健康正文。
2. **控制：** 撤销会话/密钥、隔离服务或 Provider，保全审计证据。
3. **调查：** 使用受控访问确定用户、时间范围、数据和根因。
4. **修复与恢复：** 修补、轮换、从验证备份恢复并加强监控。
5. **通知与复盘：** 根据适用义务和实际风险通知；跟踪改进项至完成。

仓库中只保存响应模板和合成演练数据，不保存真实事件的敏感证据。

## 9. 中国大陆合规基线（D-001）

以下为工程侧需要满足的最低要求，不替代法律意见。

| 事项 | 要求 | 时间点 |
| --- | --- | --- |
| ICP 备案 | 所有公网域名（主站、`auth.`、`files.`）完成备案后才开放 80/443 | Sprint 0 启动，Sprint 8 前完成 |
| 公安联网备案 | 按要求在上线后规定期限内办理，页面展示备案号 | Sprint 8 |
| 敏感个人信息单独同意 | 健康信息处理单独取得同意，与服务条款分开；AI 处理再单独同意 | Sprint 2 设计，Sprint 4/6 实现 AI 部分 |
| 个人信息保护影响评估（PIIA） | 覆盖敏感信息处理、委托 AI Provider 处理、自动化建议；记录留存 | Sprint 7 完成 |
| 委托处理 | 与 AI Provider、邮件服务、云厂商的数据处理条款存档；隐私政策列出第三方 | Sprint 4 前 |
| 数据本地化 | 所有组件和第三方处理均在境内；不使用境外 SaaS 收集日志或错误 | 持续 |
| 个人信息主体权利 | 查阅、复制（导出）、更正、删除、撤回同意、注销账号均可在产品内完成 | Sprint 7 |
| 生成式 AI | 仅对受邀家庭成员开放；向公众开放前评估备案与安全评估义务；AI 生成内容在界面中明确标识 | 持续 |
| 安全事件 | 事件响应流程包含按适用规定向用户和主管部门报告的判断步骤 | Sprint 7 |

## 10. 仍需确认的隐私决策

地域、身份服务、AI Provider、用户年龄、备份位置已在 [DECISIONS.md](DECISIONS.md) 确定。仍需确认：

- DeepSeek API 数据的保留期限、是否用于训练及删除方式。
- D-014 中各类数据的保留期限。
- 运营主体（个人/企业）、隐私联系渠道和备案主体。
