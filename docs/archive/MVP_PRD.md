# HealthOS MVP v0.1 产品需求文档

## 1. 文档信息

- 产品：HealthOS — AI Personal Health Copilot
- 版本：MVP v0.1
- 形态：移动端优先的响应式 Web / PWA
- 初始用户：项目所有者及受邀家庭成员
- 核心原则：安全基线不降级，功能范围保持克制

## 2. 产品目标

在一个可信、低摩擦的产品中完成“记录—确认—分析—计划—反馈”的健康习惯闭环。

### 2.1 成功指标（试运行 4 周）

- 受邀用户激活率 ≥ 80%。
- 活跃用户每周至少 5 天完成一类记录。
- 饮食识别结果的用户确认或修正率 ≥ 90%。
- 每周计划生成成功率 ≥ 95%，且每条建议可追溯到输入摘要。
- 0 起跨用户越权事件；关键授权测试全部通过。
- 备份恢复演练通过，恢复数据完整性可验证。

指标用于验证易用性和可靠性，不用于诱导过度记录。

## 3. 用户角色

| 角色 | 权限 |
| --- | --- |
| 注册用户 | 管理本人档案、记录、计划、同意、导出与删除 |
| 邀请管理员（admin） | 注册用户权限 + 创建/撤销邀请；不能查看他人健康数据 |
| 系统运维 | 维护服务可用性；普通管理界面无权浏览健康正文 |
| 后台任务身份 | 仅按任务范围读取必要数据，短时授权，完整审计 |

MVP 不提供家庭管理员查看成员健康数据的能力。仅面向 18 岁及以上用户。

## 4. 范围

### 4.1 P0（发布必须具备）

1. 邀请制注册、OIDC 登录、退出、会话过期和账号删除。
2. 健康档案：基础参数、活动水平、目标、偏好、过敏、运动限制；公式计算的营养参考值经用户确认后成为目标。
3. 饮食记录：拍照、识别、编辑、确认、查询、删除。
4. 运动记录：类型、开始时间、时长、强度、步数（可选）。
5. 睡眠记录：起止时间、时长、主观质量、备注。
6. 看板：今日数据、最近 7 天趋势、数据完整性提示。
7. 每日建议：基于当天饮食/运动和昨晚睡眠。
8. 每周计划：基于最近 7 天记录，可编辑、保存与反馈。
9. 数据导出：JSON 或 CSV 打包；异步生成、限时下载。
10. 隐私能力：敏感个人信息单独同意、AI 处理同意、审计、记录删除、账号删除。

### 4.2 P1（MVP 稳定后）

- PWA 安装与离线草稿。
- 站内通知和自定义记录提醒。
- 更细化的营养目标及计划执行反馈。

### 4.3 明确不在 MVP

- 医疗诊断、治疗、处方或风险评分。
- 体检 PDF、Apple Health、智能手表集成。
- 家庭数据共享、医生/营养师协作。
- 菜谱、购物清单、订阅和支付。
- 自动异常健康告警。

上述能力只保留扩展边界，不预建无实际用途的复杂实现。

## 5. 核心用户流程

### 5.1 首次使用

1. 用户通过邀请邮件链接进入，用邮箱验证码完成首次登录并设置密码。
2. 查看隐私摘要和服务边界，接受服务条款；健康信息处理单独同意；AI 处理同意可稍后单独选择。
3. 填写出生年份（未满 18 岁无法继续）、最小档案和目标；可以跳过非必要字段。若填写了身高、体重、性别和活动水平，展示热量参考值供确认或修改。
4. 进入今日首页，看到明确的首次记录入口。

### 5.2 饮食记录

1. 用户拍照或选择照片，客户端显示上传进度。
2. 服务端验证文件并保存到私有对象存储。
3. 用户明确同意后，任务将去标识化图片发送给 AI 识别。
4. 页面显示食物、份量、营养估算、置信提示和模型局限。
5. 用户修改并确认；正式统计只读取确认版本。
6. 识别失败时允许手工输入，不阻断记录。

### 5.3 每日建议

1. 系统聚合用户本地日期内的确认数据。
2. 规则层检查缺失数据、异常值和安全边界。
3. AI 基于最小化摘要生成结构化建议。
4. 服务端验证结构、禁用内容和引用的数据范围。
5. 用户看到建议、依据、局限和“不适用”反馈入口。

### 5.4 每周计划

1. 用户主动生成或由获准任务按周生成草稿。
2. 系统汇总 7 天趋势，不发送身份信息和原始图片。
3. AI 返回饮食、运动、睡眠三类行动计划。
4. 用户编辑后保存为已确认计划；原始 AI 输出单独保留。
5. 用户可标记完成、跳过或不适用，为下次计划提供反馈。

## 6. 功能验收标准

### 身份与隔离

- 任一资源 ID 被另一登录用户请求时，返回 404 或一致的无权响应，不泄露资源是否存在。
- 所有健康数据查询都从认证主体派生 `user_id`，不得信任客户端传入的所有者 ID。
- 会话撤销、过期和退出后不可继续使用受保护 API。

### 营养目标

- 参考值由确定性公式计算（Mifflin-St Jeor，见 DECISIONS D-008），展示公式输入和“非医疗建议”说明。
- 未经用户确认的参考值不作为目标参与看板对比。
- 热量参考值不低于安全下限；BMI < 18.5 或孕期/哺乳期时不提供减重目标。

### 饮食识别

- 支持 JPEG/PNG/HEIC（是否在服务端转换由实现阶段验证），限制尺寸和像素数。
- AI 结果在用户确认前不得进入正式营养统计。
- 保存原始推断、模型版本、提示模板版本、置信度和用户修订差异。
- AI 或对象存储不可用时，仍可手工记录。

### 运动和睡眠

- 时长、时间范围、强度和评分具有服务端校验。
- 支持创建、读取、修改和软删除；敏感审计记录不可由用户篡改。
- 跨时区与跨午夜睡眠按用户时区正确展示。

### 建议与计划

- 每条建议标记生成时间、输入区间和版本。
- 不生成诊断、用药、极端热量限制或危险运动建议。
- 缺少关键数据时说明不足，不虚构记录。
- 用户修改后的计划与 AI 草稿分开保存。

### 数据权利

- 用户可以请求导出，下载链接短期有效且只可本人访问。
- 删除账号需要重新验证身份和明确确认。
- 产品显示线上数据删除状态及备份淘汰时间，不作即时物理删除的虚假承诺。

## 7. 非功能需求

| 类别 | MVP 目标 |
| --- | --- |
| 可用性 | 月可用性目标 99.5%（计划维护除外） |
| 性能 | 常用读 API p95 < 500 ms（不含 AI）；写 API p95 < 800 ms |
| AI 延迟 | 饮食识别 p95 < 30 s；规划 p95 < 45 s，均异步可恢复 |
| 安全 | 关键 ASVS 控制、越权测试、依赖和镜像扫描 |
| 恢复 | RPO ≤ 24 h，RTO ≤ 4 h；发布前完成恢复演练 |
| 可观测性 | 请求 ID、结构化脱敏日志、指标、错误和审计事件 |
| 浏览器 | 当前及前一主版本 Safari/Chrome；移动端优先 |
| 无障碍 | 核心流程按 WCAG 2.2 AA 设计与测试 |

## 8. 发布门槛

- P0 验收项全部通过。
- 两个测试用户的横向越权自动化测试通过。
- AI 安全测试集和失败降级流程通过。
- 无高危依赖漏洞或公开密钥。
- 备份恢复演练有记录并通过。
- 隐私摘要、AI 同意、导出和删除流程可用。
- 产品所有页面明确显示非医疗用途和紧急情况边界（紧急情况拨打 120）。
- 所有公网域名已完成 ICP 备案。
